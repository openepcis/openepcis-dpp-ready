# CIRPASS-2 Textile Ontology — upstream mirror

**Status:** Mirror (upstream Version 1.1.2, issued 2026-07-16) • **Layer:** 2 (sectoral upstream profile of the CIRPASS-2 EU DPP pilot programme; textile working group led by GS1) • **Licence:** CC BY 4.0 (upstream, `dcterms:license`), creator per `dcterms:creator` in the ontology header

This module mirrors the **CIRPASS Textile Ontology**, the sectoral extension of
the [EUDPP Core Ontology](../cirpass2-eudpp/README.md) for textile Digital
Product Passports. Authoritative sources:

- **Documentation:** <https://cirpass-2.github.io/ontologies-docs/Textile/textile-ontology/index-en.html>
  (umbrella) and `…/Textile/textile-ontology-complete/index-en.html` (merged)
- **Files:** <https://github.com/CIRPASS-2/ontologies-docs> (`Textile/`), pinned
  by commit in `scripts/sync-cirpass2.ts`
- **Namespaces:** the umbrella `https://w3id.org/eudpp/textile-ontology` imports
  twelve modules, each with its own namespace `https://w3id.org/eudpp/textile-<module>#`
  (assessment, associated-materials, connector, context, core, durability,
  indicator, process, recyclability, repairability, soc, structure) plus two
  code-list namespaces (`textile-codelists`, `textile-associated-materials-codelists`).

## What this module ships

| File | Provenance | Purpose |
|---|---|---|
| `ontology/textile.ttl` | Generated by `pnpm sync:cirpass2-textile` — verbatim copy of `Textile/textile-ontology-complete/ontology.ttl` (the published merge of all modules) | Source of truth for the build pipeline. Preserves upstream IRIs. |
| `json/cirpass2-textile.json` | Generated by `pnpm build:json` | Vocabulary browser data for ref.openepcis.org (upstream 1.1.2 declares 399 classes, 214 properties and 281 individuals; 320 classes, 30 enumerations with 490 values and 200 properties are indexed). |

**Local names.** Five property names recur in several textile modules
(`hasTextualValue` in five, `hasCategoricalValue` and `hasQuantitativeValue` in
three, `concernsProduct` and `hasReferencePeriod` in two). The browser resolves
a term page by local name, so the build publishes those as
`<module>.<name>` (for example `textile-process.hasTextualValue`); the IRI is
unchanged. All other names stay bare.

## Relationship to the OpenEPCIS ontology

Mirroring is for **indexing and browsing only**. The OpenEPCIS textile module
(`eu/textile`, prefix `eutex:`) is a GS1-first regulation module; its alignment
to this ontology is a follow-up SKOS audit, not part of the mirror. Nothing is
imported, subclassed or rebranded. The textile SOC module uses its own
`textile-soc#` namespace, not the CORE `eudpp#` SOC terms.

## Sync

```bash
pnpm run sync:cirpass2-textile   # network: fetches the pinned file, rewrites ontology/textile.ttl
pnpm run build:json
```

When upstream releases a new version: bump `UPSTREAM_COMMIT` in
`scripts/sync-cirpass2.ts`, re-run the sync in its own commit, update `VERSION`
and record the delta in `CHANGELOG.md`.

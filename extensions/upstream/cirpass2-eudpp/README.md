# CIRPASS-2 EUDPP Core Ontology — upstream mirror

**Status:** Mirror (upstream v2.0.5, issued 2026-07-06) • **Layer:** 2 (community upstream profile — EU DPP pilot programme, input to CEN/CENELEC JTC 24) • **Licence:** Apache 2.0, CC BY 4.0 fallback as a document (upstream)

This module mirrors the **EUDPP Core Ontology** published by the CIRPASS-2
project (authored at TalTech) on the Semantic Treehouse vocabulary hub. The
authoritative source is upstream:

- **Specifications catalog:** <https://dpp.vocabulary-hub.eu/specifications>
- **Namespace / W3ID:** `https://w3id.org/eudpp#` (dereferences to the
  Treehouse Turtle exports since mid-2026)

The native namespace is preserved verbatim (preferred prefix `eudpp:`;
`dpp-core.ttl` aliases it as `cirpass2:` in its `rdfs:seeAlso` pointers). We
do **not** rebrand EUDPP terms under `ref.openepcis.org`. This module exists so
the OpenEPCIS DPP-Ready build pipeline can index the EUDPP terms into the
search and browser at <https://ref.openepcis.org>, and so the alignment
described in
[`../../common/interop/docs/CIRPASS2_ALIGNMENT.md`](../../common/interop/docs/CIRPASS2_ALIGNMENT.md)
has a browsable target.

## What this module ships

| File | Provenance | Purpose |
|---|---|---|
| `ontology/eudpp.ttl` | Generated by `pnpm sync:eudpp` — verbatim merge of the ten published module exports (CORE umbrella + ACTOR, CONNECTOR/CON, EVENT, IDENT, MAT, P_DPP, SOC, COMP, LCA) | Source of truth for the build pipeline. Preserves upstream IRIs. |
| `json/eudpp.json` | Generated by `pnpm build:json` from the TTL | Vocabulary browser data for ref.openepcis.org. |

No JSON-LD context and no SHACL are shipped: the Treehouse export API
publishes the ontology modules only (`format=ttl`/`jsonld`/`rdf`; there is no
SHACL export), and EUDPP terms are not used operationally in OpenEPCIS
payloads — the relationship is alignment, not adoption.

## Relationship to the OpenEPCIS ontology

Mirroring is for **indexing and browsing only**. Our ontology references
EUDPP terms by IRI (`rdfs:seeAlso` by default, graded SKOS mappings only
where the audit confirmed them) and adopts nothing:

- no `owl:imports` of the module files,
- no `rdfs:subClassOf` / `owl:equivalentClass` into `eudpp:`,
- the EVENT carrier layer is answered by the real GS1 EPCIS/CBV IRIs
  (see the EVENT section of the alignment doc).

## Sync

```bash
pnpm run sync:eudpp   # fetches the module exports (network!) and rewrites ontology/eudpp.ttl
pnpm run build:json   # regenerates json/eudpp.json
```

When upstream releases a new version: re-run the sync, update `VERSION` and
the inventory table above, and record the delta in `CHANGELOG.md`.

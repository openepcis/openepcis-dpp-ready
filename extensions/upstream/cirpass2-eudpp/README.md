# CIRPASS-2 EUDPP Core Ontology — upstream mirror

**Status:** Mirror (upstream v2.2.0, issued 2026-10-30; CC BY 4.0) • **Layer:** 2 (community upstream profile — EU DPP pilot programme, input to CEN/CENELEC JTC 24) • **Licence:** Apache 2.0, CC BY 4.0 fallback as a document (upstream)

This module mirrors the **EUDPP Core Ontology** published by the CIRPASS-2
project (authored at TalTech). The authoritative sources are upstream:

- **Documentation (WIDOCO, per-term anchors):** <https://cirpass-2.github.io/ontologies-docs/>
  — the module files behind it live in
  <https://github.com/CIRPASS-2/ontologies-docs> and are what this mirror is
  built from, pinned to one commit (see `scripts/sync-cirpass2.ts`).
- **Namespace / W3ID:** `https://w3id.org/eudpp#` (dereferences to the
  Semantic Treehouse hub exports, <https://dpp.vocabulary-hub.eu/specifications>).

The native namespace is preserved verbatim (preferred prefix `eudpp:`;
`dpp-core.ttl` aliases it as `cirpass2:` in its pointers). We do **not**
rebrand EUDPP terms under `ref.openepcis.org`. This module exists so the
OpenEPCIS DPP-Ready build pipeline can index the EUDPP terms into the search
and browser at <https://ref.openepcis.org>, and so the alignment described in
[`../../common/interop/docs/CIRPASS2_ALIGNMENT.md`](../../common/interop/docs/CIRPASS2_ALIGNMENT.md)
has a browsable target.

## What this module ships

| File | Provenance | Purpose |
|---|---|---|
| `ontology/eudpp.ttl` | Generated by `pnpm sync:eudpp` — verbatim merge of the ten module files (`CORE/<module>/ontology.ttl`) from `CIRPASS-2/ontologies-docs` at the pinned commit | Source of truth for the build pipeline. Preserves upstream IRIs. |
| `json/eudpp.json` | Generated by `pnpm build:json` from the TTL | Vocabulary browser data for ref.openepcis.org. |

No JSON-LD context and no SHACL are shipped: upstream publishes the ontology
modules only, and EUDPP terms are not used operationally in OpenEPCIS payloads
— the relationship is alignment, not adoption.

## Why the GitHub files and not the W3ID / hub exports

Until 2026-10 the sync read the Treehouse exports through the W3ID redirects.
Three reasons to switch (details in the sync script header):

1. the hub exports cannot be pinned, so a sync was not reproducible;
2. the hub trails the documented release by a patch level (2026-10-29: ACTOR
   2.1.3 vs 2.2.0, CON 2.3.0 vs 2.4.0);
3. on 2026-10-29 the hub export of `COMP` came back as an OWL structure dump of
   blank nodes with no IRI in it. The sync now refuses to write a module that
   declares no named ontology node or fewer terms than expected.

The W3ID IRIs remain the identity of every term; only the file source moved.

## Relationship to the OpenEPCIS ontology

Mirroring is for **indexing and browsing only**. Our ontology references
EUDPP terms by IRI (`rdfs:seeAlso` by default, graded SKOS mappings only
where the audit confirmed them) and adopts nothing:

- no `owl:imports` of the module files,
- no `rdfs:subClassOf` / `owl:equivalentClass` into `eudpp:`,
- every `cirpass2:`/`eudpp:` target in our ontologies must exist in this
  mirror — `pnpm run check:mappings` (rule 13) fails the build otherwise.

Sister mirrors: [`../cirpass2-textile/`](../cirpass2-textile/README.md)
(CIRPASS-2 Textile Ontology 1.1.2) and
[`../cirpass2-battery/`](../cirpass2-battery/README.md) (EU DPP Battery
Ontology 0.4.0 DRAFT), synced by the same script.

## Sync

```bash
pnpm run sync:eudpp   # fetches the pinned module files (network!) and rewrites ontology/eudpp.ttl
pnpm run build:json   # regenerates json/eudpp.json
pnpm run build        # check:mappings reports every pointer whose target disappeared upstream
```

When upstream releases a new version: bump `UPSTREAM_COMMIT` in
`scripts/sync-cirpass2.ts`, re-run the sync in its own commit, read the diff,
update `VERSION` and the inventory table above, record the delta in
`CHANGELOG.md`, and re-point whatever `check:mappings` now reports.

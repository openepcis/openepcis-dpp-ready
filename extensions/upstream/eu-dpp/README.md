# EU DPP Registry semantic data artifacts — upstream mirror

**Status:** Mirror (upstream release 1.0.0, issued 2026-10-30) • **Layer:** 2 (the Commission's
own data model for registering passports in the EU DPP Registry) • **Licence:** EUPL-1.2 (upstream)

This module mirrors the SKOS vocabularies of the **DPP Registry – Semantic Data Artifacts**, which
the European Commission (DG GROW, Digital Product Passport team) published on the DPP resources
page together with the Registry API guides:

- **Page:** <https://single-market-economy.ec.europa.eu/single-market/digital-product-passport/resources-documentation_en>
- **Archive:** `DPP Registry – Semantic Data Artifacts.zip`, pinned by SHA-256 in `scripts/sync-eu-dpp.ts`
- **Namespaces:** seventeen SKOS concept schemes under
  `https://repository.product-passport.ec.europa.eu/core/vocabs/<name>#` and
  `https://repository.product-passport.ec.europa.eu/product/batteries/vocabs/<name>#`

The Registry fetches a passport from its UPI over HTTPS and validates the JSON against these
artifacts (SKOS and SHACL are the master, JSON Schema and JSON-LD contexts are generated from them).
The release covers the core passport, the common supporting types and batteries with the EV, LMT
and industrial subgroups.

## What this module ships

| File | Provenance | Purpose |
|---|---|---|
| `ontology/eu-dpp.ttl` | Generated by `pnpm sync:eu-dpp`: the seventeen vocabulary files of the release merged, triples unchanged | Source for `build:json`, the vocabulary browser and vocab-sync |
| `json/eu-dpp.json` | Generated by `pnpm build:json`: data elements as properties (domain and range from the Commission's SHACL shapes in `vendor/eu-dpp/`), `DigitalProductPassport` as a class, value lists and error codes as one enumeration per concept scheme | Vocabulary browser data for ref.openepcis.org |

The complete release (contexts, SHACL shapes, JSON Schemas, conformance examples) lies verbatim
under [`vendor/eu-dpp/1.0.0/`](../../../vendor/eu-dpp/README.md), with a manifest of file hashes.

## What the vocabularies hold

| Kind | Schemes | Concepts | How they relate to us |
|---|---|---|---|
| Data elements | `core-vocabulary`, `common-vocabulary`, `battery-vocabulary` | 110 | Each concept is a passport field; the Commission's SHACL shapes use it as `sh:path` (109) or `sh:targetClass` (`DigitalProductPassport`). The release types them only there, so the JSON view lists them as properties and a class with the datatype, value list or class the shapes require. Aligned with graded SKOS relations from our properties, like any upstream property. |
| Value lists | `battery-category`, `battery-chemistry`, `battery-chemical-symbol`, `battery-status`, `critical-raw-material`, `measurement-unit`, `granularity-level`, `instance-status`, `information-type`, `battery-information-type`, `observed-characteristic` | 77 | Code values, matched value by value with `skos:exactMatch` from our individuals. |
| Error codes | `core-error-code`, `common-error-code`, `battery-error-code` | 107 | Registry validation errors. Mirrored for completeness; nothing of ours corresponds to them. |

## Relationship to the OpenEPCIS ontology

Mirroring is for **indexing, browsing and checking pointers** (`check:mappings` rule 14 rejects
any pointer into these namespaces that the mirror does not hold). Nothing is imported, subclassed
or rebranded. Our terms anchor to the EU data elements under the prefixes `eudppcore:`,
`eudppcom:` and `eudppbat:`; the rendering of a passport into the Registry's JSON lives in the
dpp-api (`representation=eu`), not here.

## Known issues in release 1.0.0

Every IRI points at `repository.product-passport.ec.europa.eu`, a host that had no DNS record when
the release came out (NXDOMAIN on 2026-11-02 from the zone's own name servers). The rest is listed
in [`vendor/eu-dpp/README.md`](../../../vendor/eu-dpp/README.md).

## Sync

```bash
pnpm run sync:eu-dpp                        # network: downloads the pinned archive
pnpm run sync:eu-dpp -- --from <file.zip>   # or from a local copy of the same archive
pnpm run build:json
```

A download whose hash differs from the pinned one is refused, because the Commission replaces
documents under the same link. For a new release: inspect the archive, bump `RELEASE` and the
concept minima in `scripts/sync-eu-dpp.ts`, sync in its own commit, update `VERSION` and record
the delta in `CHANGELOG.md`.
